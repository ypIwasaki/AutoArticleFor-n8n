# AutoArticleFor-n8n

This repository stores n8n workflow definitions and operating notes for a daily
keyword-based news and web-content summarization project.

## What is included

- `n8n/workflows/daily-keyword-news-summary.workflow.json`
  - Importable n8n starter workflow for daily keyword monitoring.
  - Runs on a daily schedule, manual trigger, or webhook request.
  - Reads Google News RSS and Hatena Bookmark RSS search results for configured keywords.
  - Produces a Markdown digest, structured article records, and compact AI task instructions.
- `n8n/workflows/auto-article-starter.workflow.json`
  - Earlier article-brief prototype. Prefer the daily keyword summary workflow
    for the current project direction.
- `docker-compose.yml`
  - Optional local n8n runtime using the official n8n container image.
- `.env.example`
  - Example local n8n environment variables. Do not commit real secrets.
- `docs/n8n-setup.md`
  - Setup, import, test, and workflow development notes.
- `docs/n8n-api-sync.md`
  - API-based sync instructions for updating an existing n8n workflow from this repository.
- `docs/ai-keyword-extraction.md`
  - Notes for the AI keyword extraction instruction Markdown generated by the workflow.
- `docs/ai-summary-instructions.md`
  - Notes for the AI article-summary instruction Markdown generated by the workflow.
- `docs/ai-rules/`
  - Reusable rules for summary, keyword extraction, talent indexing, classification, and weekly reporting.
- `scripts/read_ai_inputs.py`
  - Read-only, paginated input reader for those five AI tasks.
- `content/`
  - Daily article archives, compact AI task instructions, and reviewed outputs.

## Quick start with npm

With n8n installed, start it with project file access:

```bash
bash scripts/start_n8n_with_file_access.sh
```

Open `http://localhost:5678`, then import:

```text
n8n/workflows/daily-keyword-news-summary.workflow.json
```

## Quick start with Docker

```bash
cp .env.example .env
docker compose up -d
```

Open `http://localhost:5678`.

## Workflow test payload

Use this JSON body with the webhook test URL:

```json
{
  "keywords": ["Vtuber", "にじさんじ"],
  "lookbackHours": 24,
  "locale": "ja-JP",
  "language": "ja",
  "country": "JP",
  "outputLanguage": "ja"
}
```

`maxArticles` を省略すると、期間内で重複除去後に取得できた全記事を保存し、要約指示書の対象にします。必要な場合だけ正の整数を指定して件数を制限できます。

In n8n test mode, the webhook URL is usually:

```text
http://localhost:5678/webhook-test/daily-keyword-summary/request
```

After activating the workflow, use:

```text
http://localhost:5678/webhook/daily-keyword-summary/request
```

## Markdown archive

When the workflow runs, it saves Markdown files under:

```text
content/daily-digests/
content/keyword-candidates/
content/ai-extraction-instructions/
content/ai-summary-instructions/
content/ai-talent-index-instructions/
content/ai-article-classification-instructions/
content/ai-weekly-report-instructions/
```

The daily digest file stores the collected articles and source-based digest. The
keyword candidate file extracts follow-up terms from the saved digest, with a
focus on VTuber agencies, groups, companies, and related terms. Version 2
instruction files contain the task/date and references to reusable rules, inputs,
and outputs; they do not embed the article list, full digest, or search keyword
list. Daily JSONL records remain under `content/structured-records/`. The workflow
does not call AI APIs automatically.

## Start n8n with project file access

To let n8n write generated Markdown into this project, start n8n with:

```bash
./scripts/start_n8n_with_file_access.sh
```

If n8n is already running, stop it first and start it again with this script.
The script detects the checkout root as `PROJECT_ROOT`; Docker Compose uses
the container mount `/project`. Workflow configuration reads and archive
writes use this root, so cloning to another directory needs no path edits.
Existing n8n workflows must be imported/synced after this definition changes.
Data Table initialization and environment-specific table IDs still need setup;
see [file access settings](docs/n8n-setup.md#file-access-setting).

## AI extraction instructions

The project-scoped operational skill is
[`autoarticle-operations`](.agents/skills/autoarticle-operations/SKILL.md).
Use `$autoarticle-operations` to request n8n startup, article work, and review-app
launch within the requested scope. Its instructions and UI metadata live in
`.agents/skills/autoarticle-operations/` alongside the project, so include them
in commits when sharing the repository. A separate personal skill copy is not
needed. Runtime dependencies, credentials, and local n8n data still require
their own setup on another PC.

Routine command entry point (WSL/Linux, from the project root):

```bash
python3 scripts/autoarticle_ops.py status
python3 scripts/autoarticle_ops.py start n8n
python3 scripts/autoarticle_ops.py collect
python3 scripts/autoarticle_ops.py --date YYYY-MM-DD resume
python3 scripts/autoarticle_ops.py --date YYYY-MM-DD apply
python3 scripts/autoarticle_ops.py start dashboard
```

Run only commands authorized by the request. `collect` sends a real request for
today (JST); `apply` writes reviewed proposals to n8n, talent/articles first.
It requires current review checkpoints. `status` and `resume` are read-only.
See [operation commands and evidence](docs/autoarticle-operations.md) for review
checkpoints, configuration, stopping conditions, and resuming incomplete work.
Local progress lives in `.operation-state/` (not Git); a clone does not inherit
the current machine's completion state. The skill and scripts remain in Git.

Per-step Codex token usage can be recorded with `tokens bind`, `tokens begin STEP`,
and `tokens finish` on the same entry point. Successful review checkpoints close
matching measurements. Daily Markdown/JSON reports are generated in
`content/operation-usage/`; `tokens report` refreshes delayed observations.
Work dates (JST) and article target dates are separate. Missing values stay
unmeasured; unassigned intervals retain their before/after cumulative difference.
See [token measurement and attribution](docs/token-usage.md) before initial setup.

For routine operations, first read the short [operation result rules](docs/ai-rules/operation-result.md)
once per run. Report the completed scope, key verified counts, unresolved items,
and the review link in a few lines. Use [the log-preserving command wrapper](docs/operation-results.md)
when command output would be large; keep full logs local and inspect details only
when needed. This changes reporting, not article review or validation requirements.

Read the generated instruction, then its `rulesPath`, and use the input reader
from the project root to read the task's article data in batches:

```bash
python3 scripts/read_ai_inputs.py --run-date YYYY-MM-DD --task article-summary --offset 0 --limit 20
```

Pass the returned top-level `nextOffset` as `--offset` until `nextOffset` is
`null`, so that all articles have been considered.
Supported tasks are `article-summary`, `keyword-extraction`, `talent-index`,
`article-classification`, and `weekly-report`. The first batch supplies shared
run metadata; later batches avoid repeating it. Summary, talent-index, and
classification views join body text by URL, with capture status and continuation
information for long text. Keyword views return article metadata and source
references. Weekly views default to validated compact metrics; use
`--weekly-articles` explicitly for raw article pages. Use the article's run date
and the summary task for its body.
Use the referenced source files for evidence not included in the selected view.

`totalArticles`, `returnedArticles`, and `nextOffset` describe article pagination.
For long text, `content.nextOffset` is the character offset for the next request;
`content.complete` describes whether the selected saved text has been fully
returned, not whether the original article was successfully captured. `not_captured`
means no capture row exists, while `unavailable` records a failed capture.

These instructions work with Codex or another agent that can read this
repository. An external AI chat needs the referenced rules and relevant data
attached as well; pasting a version 2 instruction alone is insufficient.
Existing archived instructions and article/proposal formats are retained.
See `docs/ai-summary-instructions.md` and `docs/ai-keyword-extraction.md`.

New instructions also declare their `inputMode`: shared-review-first for
summary/talent/classification, article-metadata for keyword extraction, and
weekly-metrics for the weekly report. Shared review paths and the validated
writer are referenced explicitly. Weekly instructions include the exact metrics
JSON path, evaluation cutoff, and separate commands for preparation and
post-edit synchronization/validation. See [the generator contract](docs/n8n-setup.md#integrated-instruction-metadata-and-commands).

## Shared body-review facts

Summary, talent indexing, and classification prefer a validated shared review
in `content/article-review-facts/YYYY-MM-DD.jsonl`. Read
[the shared review rules](docs/ai-rules/shared-article-review.md) alongside the
task rules. A current `ready` record supplies grounded facts instead of another
copy of the body; `held` preserves the unresolved reason. Missing, stale,
invalid, or task-incomplete records fall back to body reading.

The reviewer authors the facts; the saver does not infer semantic approval:

```bash
python3 scripts/save_article_review_facts.py --run-date YYYY-MM-DD --input REVIEW_JSON --check-only
python3 scripts/save_article_review_facts.py --run-date YYYY-MM-DD --input REVIEW_JSON
```

Use `read_ai_inputs.py ... --include-body` to inspect or reconsider a cached
review. Source/rule hashes and exact evidence ranges are checked before reuse.
Unchanged verified-body inputs can reuse prior-date facts; non-body reviews
are reconsidered each date. Existing summaries/proposals and human approvals
are not converted automatically. The heuristic proposal generator is still a
draft tool, not the shared review producer. No n8n execution, AI API, or DB
write is performed by the input reader or fact saver.

## Weekly analysis

Each n8n run also writes `content/structured-records/YYYY-MM-DD.jsonl` for reusable analysis. Backfill existing Markdown digests and generate the latest weekly reports with:

```bash
python3 scripts/backfill_structured_records.py
python3 scripts/generate_analysis_reports.py
```

The canonical numbers are saved in `content/analysis/weekly-metrics/YYYY-Www.json`;
both analytical Markdown reports are generated from that same snapshot.
Use `--through YYYY-MM-DD` for the collection cutoff, `--as-of YYYY-MM-DD`
for a later evaluation cutoff, and `--check` to detect stale inputs or altered
outputs without writing. Missing full feedback JSON produces provisional
numbers; `--require-feedback` prevents that. See [the analysis workflow](docs/analysis.md)
for report synchronization, count definitions, and limitations.
## Manual keyword management

Edit `config/keywords.json` to add or remove keywords from the default daily
search. The workflow reads this file at the start of every run, so the next
scheduled, manual, or keyword-unspecified webhook run uses the saved changes.
See `docs/keyword-management.md` for the JSON schema and the interaction with
automatically promoted keywords.

## Automatic keyword promotion

The workflow promotes high-confidence agency and unit names from captured articles into n8n workflow static data. Promoted terms are combined with the manual list in `config/keywords.json` on the next scheduled search. See `docs/automatic-keyword-promotion.md` for the policy and webhook behavior.

## Talent/article index

The daily workflow generates AI instructions for talent/article indexing and
reads only approved, search-enabled talents as future default search keywords.
Reviewed proposals are applied through a separate workflow to `talents`,
`articles`, and `article_talents`, which supports multiple talent associations
per article. See `docs/talent-article-index.md`.

## Article classifications

The daily workflow also writes an AI review instruction for article type,
category, and relevance. Reviewed proposal JSON is applied through a separate
workflow to the `article_classifications` Data Table. See
`docs/article-classifications.md` for the taxonomy and setup.

## Talent Index dashboard

Run the local read-only dashboard to browse the n8n `talents`, `articles`,


## AI weekly research reports

After every daily workflow run, n8n creates a weekly report instruction in
content/ai-weekly-report-instructions. Its filename is the Monday (JST) of
the current week. Process that instruction alongside the daily AI instructions
and save or update the matching report in content/weekly-reports.

A week runs from Monday through Sunday in JST. Until Sunday, every daily run
updates the same report file with the full collection range available so far.
A new Monday starts a new report. Reports distinguish body-verified article
summaries from video metadata summaries and document missing or noisy data.
The reusable policy is `docs/ai-rules/weekly-report.md`. First generate metrics
with `generate_analysis_reports.py --through SOURCE_RUN_DATE`, then use the
`weekly-report` reader for compact numbers and missing days. Read reviewed
sources only as needed for interpretation; do not recount all article pages.
Use `--sync-report REPORT_PATH` to update the report's numeric block while
preserving prose, then `--check --check-report REPORT_PATH` to verify that block
and analytical outputs. Prose and its factual claims still require review.
See `docs/analysis.md`.

## Article review Markdown

Collected article pages can be converted to reviewable Markdown while preserving
headings, paragraphs, lists, links, and other semantic content. One canonical file
and review field is created per article; keyword folders contain generated references
so multi-keyword matches do not create conflicting copies.

```bash
python3 scripts/capture_article_contents.py --run-date YYYY-MM-DD --retry-unverified
python3 scripts/generate_article_review_markdown.py --date YYYY-MM-DD --clean-generated
python3 scripts/apply_article_markdown_reviews.py --date YYYY-MM-DD
```

For a long historical backfill, use the resumable runner. It checkpoints every
article URL as well as every completed date.

```bash
python3 scripts/run_article_review_history.py --stop
python3 -u scripts/run_article_review_history.py --resume --max-retries 1
```

See `docs/article-review-markdown.md` for grouping, tie handling, review values,
and batch application instructions.

Start the local browser reviewer to inspect and evaluate Markdown quickly:

```bash
python3 scripts/article_review_viewer.py
```

See `docs/article-review-viewer.md` for viewer usage and keyboard shortcuts.
