# 運用結果の返答ルール

このルールは同じ運用中に一度だけ読む。記事確認・成果物・検証は省略せず、通常の最終報告を3〜5行程度にする。詳しい説明を求められた場合と、障害対応に必要な場合は長くしてよい。

- 対象日、完了した範囲、既存の検証結果にある主要件数、保留・未完了、確認ページまたは成果物のリンクを返す。
- 全コマンド履歴、全ファイル一覧、本文、候補一覧、詳細ログを再掲しない。返答用に全件再読・手集計しない。
- 未確認・未計測を0件にしない。取得成功、本文確認、成果物完成、DB反映、HTTP疎通、ブラウザで開いた状態を混同しない。終了コード0やファイル存在だけで全工程完了としない。
- 失敗、警告、採否未反映の暫定値、欠損、保留は省かない。失敗した工程・短い原因・完了済み範囲・次の対応を伝える。再試行前に二重実行がないか確認する。
- 作業中の必要な経過連絡は続け、詳細ログの逐次転記はしない。依頼範囲外の収集・反映・プッシュを追加しない。
- 運用コマンドは必要に応じて `scripts/operation_result.py` で詳細ログをローカル保存し、短いJSONを読む。使い方や障害調査の時だけ [詳細手順](../operation-results.md) を参照する。本文・根拠を読む入力リーダーは短縮対象にしない。
- 保存手段のない外部AIでは既存の成果物全文出力契約を優先し、短い報告だけで成果物を欠落させない。

例（確認した値だけを記載）：

```text
対象：YYYY-MM-DD。収集・記事作業・検証まで完了しました。
収集：N件／今回の要約完成：M件／保留：K件。
確認ページ：実際に確認して開いたURL
```
