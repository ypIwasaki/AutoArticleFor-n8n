# DB集約 フェーズ1のバックアップと復元

対象は `database-consolidation-work-instructions.md` のフェーズ1のみ。既存Data Tablesと既存ファイルを正本のまま保持する。AI入力の項目・本文量・確認基準は変更しない。

## 実行前

- n8n、記事収集・本文取得・レビュー保存・提案反映・評価保存を実行しない時間帯を確保する。
- WindowsとWSLの両方で対象プロセスを確認する。スクリプトの自動プロセス検査はWSL側だけなので、Windows側の確認を省略しない。
- n8nの `execution_entity` に new / running / waiting がないことを確認する。該当すれば停止し、勝手にプロセスを終了しない。
- 十分な空き容量を確保する。内部DBは元DBのほか、バックアップと復元試験用の2個分が必要。

## バックアップ

WSLのプロジェクトルートで実行する。対象日は実際に保存済みの日次ファイルの日付を指定する。

```sh
python3 scripts/database_phase1.py --run-date 2026-09-14
```

毎回 `.operation-state/database-consolidation/<UTC日時>/` を新設する。既存のバックアップは上書きしない。

- `n8n.sqlite`: SQLite backup APIによる整合した内部DB全体の写し。
- `files/`: 集約対象ファイル、および代表出力に必要なコード・規則・設定・補助ファイルの写し。補助ファイルはDB移行対象の拡張を意味しない。
- `input-files.json`: 相対パス、バイト数、SHA-256。
- `database-baseline.json`: 全6テーブルの列・型・索引・制約・件数・行内容ハッシュ、業務キー重複、参照不一致、状態内訳。
- `known-conflicts.json`: URL重複・関係重複・参照不一致。自動修正しない。
- `credential-scan.json`: ファイル検査の結果。検出値は出力しない。既知形式の検査であり、任意形式の秘密値の不在を保証するものではない。
- `restore-test.sqlite`: バックアップから別DBへ復元した試験用DB。
- `representative-outputs/`: 現行確認アプリ・週次集計・AI入力リーダーの出力と呼出条件。
- `phase1-result.json`: 完了または停止状態、検証結果、時刻。

内部DB全体にはn8nの認証管理領域も含まれる。バックアップは復旧専用の機密ファイルとしてGit対象外領域に保持し、移行入力・共有資料・ログへ取り出さない。作成時のumaskは077。`.env`、n8nの暗号鍵設定、生の認証値は資料に転記しない。元のn8n環境・暗号鍵設定は保持する。

## 復元試験

スクリプトはバックアップを読み取り専用で開き、backup APIで別DB `restore-test.sqlite` へ復元する。元DBには復元しない。

次をすべて確認してからフェーズ1を完了にする。

1. バックアップと復元先の `PRAGMA integrity_check` がともに `ok`。
2. 復元先の全6テーブルについて、列・型・件数・行内容ハッシュ・重複・参照不一致・状態内訳がバックアップと一致。
3. コピーしたファイルのSHA-256が台帳と一致し、作業終了時にも元ファイルの一覧・サイズ・ハッシュが同じ。
4. 作業終了時の元DBの基準値がバックアップと一致。
5. 代表出力を取得でき、確認アプリが提案ファイルへフォールバックしていない。
6. 作業前後に書き込み処理が稼働していない。

バックアップからファイルを検証する場合は `files/<台帳のpath>` のサイズとSHA-256を比較する。復旧演習は元ファイルへ上書きせず、別ディレクトリへコピーして行う。

## 実際の切戻し

フェーズ1では元DBと元ファイルを変更しないため切戻しは不要。作成したバックアップ・調査結果を保持する。

後続フェーズで復旧が必要な場合は、まず全書き込みを停止し、現在のDB・WAL・SHM・ファイルを別の復旧地点に保全する。試験用ディレクトリにバックアップを復元し、上記検査を再実施する。元DBの接続が残った状態でDB単体を置換しない。DBと対象ファイルの復旧地点を揃え、n8nの既存暗号鍵設定を保持する。専用DBだけに新しいデータがある場合は、そのデータを旧経路へ戻せることを検証するまで旧経路を再開しない。

## 停止と再開

入力変化・書き込み実行中・認証情報混入・バックアップ不整合・件数取得不能・復元未確認・未説明差分があれば、後続フェーズへ進まない。`phase1-result.json` と残った成果物を保持する。対象・根拠・再開条件を別途記録し、原因解消後は新しい日時ディレクトリでフェーズ1を最初から再実行する。
