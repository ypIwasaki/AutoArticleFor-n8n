## 初回停止の根拠（再開前の履歴）

[作業指示書](database-consolidation-work-instructions.md)の第6節は「すべての接続でforeign_keysを有効にする」、フェーズ2の中止条件は「foreign keyが無効」の場合に停止すると規定している。

基本の8テスト（再実行、バックアップ復元、部分保存取消し、制約、移行途中失敗、認証、SQL API非公開、外部アドレス拒否等）は成功した。その後、共通層以外から作るバックアップ先接続も含む追加検証を行い、次を観測した。

| 検査対象 | 元接続 | 宛先接続 |
| --- | ---: | ---: |
| `project_database.backup()` | foreign_keys=1 | **foreign_keys=0** |
| `project_database.restore_check()` 内のバックアップ | foreign_keys=1 | **foreign_keys=0** |

原因は `project_database.backup()` が宛先に `sqlite3.connect()` を直接使用し、外部キーを有効にしていないこと。復元確認も同じ経路を利用する。検証は隔離した一時DBに対して実施し、バックアップ実行時点の両接続のPRAGMAを観測した。意図的な制約エラーの注入試験とは別の、未充足要件である。

機械可読の結果: [database-phase2-verification.json](database-phase2-verification.json)。

利用者の中止条件に従い、この発見以降は記録作成だけを行った。問題を未解決のまま完了扱いにせず、フェーズ3への変更を追加していない。
